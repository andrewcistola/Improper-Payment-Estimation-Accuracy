# Robustness and calibration runs (Appendix D)

The main results rest on three things that 25 audit years per program cannot test on their own. This folder tests them with the same code, designs and methods.

| Question | Run | Output |
|---|---|---|
| **Is the parametric interval as wide as the estimator's own sampling variability?** With 25 audit years, coverage of 23, 24 and 25 cannot be told apart (Monte Carlo SE about 4.4 points). Over 100 audit years, the half-width of each interval is compared with the empirical standard deviation of the point estimate; the ratio half-width ÷ (1.96 × SD) should be near 1. | `python robustness/run.py --only calib` (base populations, parametric rates, 500 iterations) | `results/<program>/calibration/`, `results/summary_calibration.csv`, Table D1 |
| **Does the simulation's advantage survive when its implicit model is wrong?** The populations fabricate errors independently of payment size within each stratum, which is also what the simulation assumes when it borrows count-based rates from the audit and takes every unit's size from the population. Each population is rebuilt with `size_beta = +0.5` and `−0.5` (error probability × (payment / stratum mean payment)^size_beta, capped at 0.95, then calibrated to the same public targets) and re-estimated with every method. Part D, whose error rates are stated count rates with no dollar target, uses `size_beta = ±0.25` with the two count rates rescaled so that its true gross rate stays at the base 1.38% (see `run.py`). | `python robustness/run.py --only beta` | `output/<program>/beta_*/` (manifests committed, parquet not), `results/<program>/beta_*/`, `results/summary_beta.csv`, Tables D2–D3 |
| **Does post-stratifying the simulation's donor kinds by payment size recover what size-dependent errors cost it?** With `sim_kind_deciles = 10` the simulation's donor kinds (Part D, PERM, EIPM, CERT) become each design stratum × 10 equal-count quantiles of the payment variable within it (submitted GDC, payment, annual APTC, amount paid; computed on the population), so a non-audited unit only receives findings from audited units of about its own size. The audit design, strata, allocation and the analytic estimators are unchanged, so only the simulation rows move; a kind with no audited unit borrows its parent stratum's pooled rates. Run on the base populations and on both `size_beta` populations (requires `beta` first). Part C is excluded: its HCC donor kinds already carry the structure. | `python robustness/run.py --only d4` | `results/<program>/base_k10/`, `results/<program>/beta_*_k10/`, `results/summary_k10.csv`, Tables D4–D6 |

`python robustness/run.py` runs all three (`beta`, `d4`, `calib`) and then `summarize.py`, which writes the CSVs and `manuscripts/generated/appendix_d.md` (assembled into the manuscript by `manuscripts/scripts/assemble.py`). The whole set takes about 3 to 4 hours on a 2-core machine (the CERT runs use `--memory-limit 3GB`; 8 GB of memory is enough). `size_beta` is a variable in every program's `errors/config.yaml` (default 0.0, under which the base populations are byte-identical to the published ones); see each program's `*apply_errors*.sql` header for how it enters the error probability and the calibration.
